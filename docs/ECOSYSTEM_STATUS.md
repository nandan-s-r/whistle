# Whistle ecosystem status - 4 October 2026

This register tracks the connected investment workflows and the 30 product questions that shaped them. Start with a weekly review of changed evidence and unresolved decisions. The tables record what was built and what still needs work; they do not establish customer demand or a finished ecosystem. See [deployment status](DEPLOYMENT.md) for the current hosted setup.

## Primary recurring job

Start with a weekly review of changed investment premises: inspect new observations, outstanding conditions and competing views, then record a human decision. This follows the user's reason for returning next Monday. It is a product choice, not proof that investors will pay for it. Review-outcome counts begin measuring whether drafts are approved and completed diligence affects a view. Pricing, buyer identification, actual time saved and cost per useful task still require observed usage.

## Financial basis

Operating forecasts record sourced starting revenue/ARR, definitions, currency, period and yearly growth, gross margin and expenses. Recognized revenue and year-end ARR compound independently. Gross profit is revenue × gross margin. Operating contribution is gross profit less entered operating expense and is not net profit or cash flow. Debt, taxes, working capital, capex and financing are excluded.

A return version can bind an owned USD forecast only when horizon and terminal ARR match. Another currency requires a supported FX assumption; no conversion is invented. Frozen versions retain the complete forecast and its sources. Excel exports add the formula-driven operating build while preserving the existing return scenarios and source register. This does not establish a full three-statement model, cap table or real-company input quality.

## Access and integration release gates

Fund records are explicit reviewed copies of a personal record and its history. The original remains separate. All members need current membership; non-admins also need a deal grant. Reviewer grants are capped by membership role. Revoked users cannot retrieve, export or compare the record. Private personal files, vector indexes and background jobs are not shared; fund jobs refuse to queue until those permissions are designed.

The dedicated Supabase project's matching schema is applied and database-tested. Cloud fund access is disabled by default with `FUND_ACCESS_ENABLED=false`. Actual cloud user/API/browser authorization, hosted Auth confirmation, Storage HTTP behavior, worker behavior, Realtime and revocation under real JWTs still need verification before enabling it. Recorded grants and SQL fixtures do not substitute for those checks.

No licensed funding/people feed, unrestricted LinkedIn search, live news subscription, OAuth CRM/email/calendar integration, Zapier workflow, telemetry delivery or production deployment was added. An installed chat connector is not an application integration. Calendar exports do not deliver invitations. Provider keys remain private. Autonomous investment decisions, unrestricted harvesting, fund accounting, premature fine-tuning and large agent teams remain excluded.
